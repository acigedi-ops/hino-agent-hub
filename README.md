# Rhino Agent Hub

Private web app for Rhino Insurance agents: prospects, pipeline, the Rhino intake form, clients and policies.
EZLynx remains the system for rating and policy records.

## What phase 1 includes

- Sign in for each person. Agents see only their own contacts, owners see everyone.
- Leads and a pipeline: Lead, Prospect, Quoting, Quoted, Lost. A contact becomes a Client when a bound policy is added and a Former client when the last policy ends.
- Duplicate protection by phone and email across all agents.
- The Rhino intake form on screen, saved per contact and produced as the branded one-page PDF.
- Clients list with totals, renewals in the next 90 days, lost quotes with requote dates.
- Owner admin: create logins, disable logins, reset passwords, reassign contacts.

Not yet built: reminders by email, messages, My Documents, AI intake, commissions, EZLynx import, two-step login.

## Run it locally

Requires Node 20+ and Postgres.

```bash
cp .env.example .env        # then edit the values
npm install
npx prisma migrate deploy   # creates the tables
npm run db:seed             # creates the first owner login from .env
npm run dev                 # http://localhost:3000
```

## Checks

```bash
npm test        # unit tests, including the PDF template field check
npm run lint
npm run build
```

## The intake PDF

`public/forms/rhino-intake-template.pdf` is generated by `tools/make_intake_template.py` (Python, needs `reportlab` and `pillow`).
Its field names must match `src/lib/intake.ts`; `npm test` fails if they drift apart.

## Security notes

- Passwords are stored as bcrypt hashes. Sessions are random tokens stored hashed, in an httpOnly cookie.
- Every data query is scoped to the signed-in user in `src/lib/auth.ts` (`contactScope`).
- The intake form deliberately has no fields for card or bank account numbers.
- Never commit `.env` or real client data.
